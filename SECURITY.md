# Security policy

Only the current application revision on maintained, patched runtimes is supported.
Run the security workflow before upgrades and preserve database and storage backups.
See [deployment and recovery](docs/security/upgrade.md),
[baseline](docs/security/baseline.md) and [remediation status](docs/security/remediation-report.md).

Report suspected vulnerabilities privately through the repository's GitHub
Security Advisories reporting facility when enabled. Otherwise contact the
repository maintainer privately through their GitHub profile to arrange a secure
channel before sharing exploit details. Do not include credentials, customer
records, private archives or a public proof of exploit in an issue. Include the
version/commit, deployment mode, affected route/component, impact and a minimal
reproduction using synthetic data. Coordinate disclosure with the maintainer;
no response-time guarantee is currently offered.
